# 8小时工作台 Web 前端样式规范

> 版本：v1.0
>
> 生效日期：2026-10-27
>
> 适用范围：`workcove-web` 全部页面、组件和新增前端能力
>
> 相关文档：[架构与分包](../../ARCHITECTURE.md)、[Git 分支规范](./Git分支规范.md)

## 1. 设计定位

8小时工作台的界面目标是：** macOS 原生应用的空间关系 + 研发工作台的克制与效率 **。

它不是 macOS 组件库的机械复刻，也不是通用后台模板。最终观感应满足：

1. 默认白色，浅色 / 深色 / 跟随系统三态完整。
2. 窗口、工具栏、侧边栏、弹窗具有 macOS 的层级与材质感。
3. 信息密度高于普通网站，但正文和控件不能靠 7–10px 小字硬塞。
4. 颜色只承担状态和交互含义，不用大面积渐变、彩色卡片或装饰色块制造“设计感”。
5. 研发工具的气质来自精确的排版、稳定的布局和清晰的反馈，不来自终端字体的滥用。
6. 8小时工作台保留自己的识别点：深色玻璃时间组件、Launchpad 式快捷入口、白色工作画布。

## 2. 规范优先级

前端实现发生冲突时，按以下顺序取值：

1. `workcove-web/src/styles/tokens.css`：颜色、字体、尺寸、圆角、阴影、动效的唯一来源。
2. `workcove-web/src/components/ui/`：按钮、输入框、字段和分段控件的统一实现。
3. 本规范：组件选择、页面结构和交互约束。
4. 业务页面局部样式：只允许处理布局，不允许重新定义基础视觉语言。

新增视觉值前先确认现有令牌能否表达。连续两次出现同一种局部样式时，应抽成 `components/ui/` 组件。

## 3. 字体与字号

### 3.1 字体栈

默认字体栈：

```css
system-ui, -apple-system, BlinkMacSystemFont, "SF Pro Text",
"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif
```

- 必须通过 `var(--font-sans)` 使用。
- 设置页允许在“系统”“Codex”“Avenir”之间切换，偏好按登录账号保存。
- Codex 风格使用本地内置的 Inter 字体和苹方中文回退，不依赖网络加载。
- Avenir 风格使用 macOS 自带的 Avenir Next，并以苹方作为中文回退。
- 代码、时间、ID、路径等需要等宽对齐的内容使用 `var(--font-mono)`。
- 不在业务组件里直接写 `"SF Pro Display"`、`"Helvetica Neue"` 或第二套字体。
- 不打包专有字体冒充 SF Pro；可打包许可清晰的 Inter。

### 3.2 字号

| 令牌 | 值 | 用途 |
|---|---:|---|
| `--font-caption` | 11px | 辅助说明、字段提示、表头、元信息 |
| `--font-body` | 13px | 正文、按钮、输入框、菜单 |
| `--font-title` | 15px | 分区标题、检查器标题 |
| `--font-metric` | 22px | 指标数字 |
| `--font-display` | 28px | 工作台主标题 |
| `--font-hero` | 34px | 登录页等封面级标题 |

硬约束：

- 业务界面不得出现小于 11px 的字号。
- 表单控件统一 13px，不因局部空间不足缩成小字。
- 中文强调优先使用 `--weight-emphasis`（500）；600 只用于表头、等宽数字和极少量强强调。
- 数字统计使用等宽数字样式，避免数值变化时左右跳动。
- 不使用负字距。

`pnpm check:ui` 会阻止小于 11px 的字号和直接写死的字体栈。

## 4. 颜色

### 4.1 系统语义色

| 语义 | 浅色 | 深色 |
|---|---|---|
| 主操作 / 运行中 | `#007AFF` | `#0A84FF` |
| 错误 / 删除 | `#FF3B30` | `#FF453A` |
| 待处理 / 警告 | `#FF9500` | `#FF9F0A` |
| 完成 / 正常 | `#34C759` | `#30D158` |
| 中性 | `#8E8E93` | `#98989D` |

业务组件使用 `var(--system-blue)`、`var(--system-red)` 等令牌，不写十六进制颜色。

### 4.2 文本

| 令牌 | 用途 |
|---|---|
| `--text` | 标题、正文、控件值 |
| `--text-muted` | 说明、次要标签 |
| `--text-subtle` | 提示、占位、时间等低优先级信息 |
| `--placeholder` | 输入占位符 |

文本颜色必须使用语义标签色。深色模式不是简单反色，必须由主题令牌自动切换。

### 4.3 表面

| 令牌 | 用途 |
|---|---|
| `--canvas` | 页面画布、窗口背景 |
| `--canvas-raised` | 内容卡片、面板 |
| `--sidebar` | 侧边栏 |
| `--material` | 工具栏、标题栏、浮层材质 |
| `--window-material` | 弹窗材质 |
| `--control-bg` | 按钮、输入框、分段控件滑块 |
| `--surface-inset` | 卡片内部的次级控件、计数和标题图标底板 |
| `--surface-secondary` | 资料页分栏、只读区域等次级表面 |
| `--asset-tile-bg` | favicon、App 图标等外部资源图标底板 |
| `--category-chip-bg` | 分类、标签等元数据底板 |

材质只用于标题栏、侧边栏、工具栏、菜单和弹窗。列表行和大面积内容区不得使用 `backdrop-filter`。

深色模式表面规则：

- 卡片内部的次级控件使用 `--surface-inset`，不能直接使用页面画布 `--canvas`，避免形成突兀的近黑色方块。
- 外部 favicon / App 图标使用 `--asset-tile-bg` 和 `--asset-tile-border`，保证透明背景图标在深色主题下仍然可辨认。
- `--asset-tile-icon` 只用于图标资源加载失败时的线性占位图标。
- 分类标签在深色模式使用中性 `--category-chip-*` 令牌，不使用高饱和蓝色底板；系统蓝只保留给选中态和主操作。
- 表单输入统一使用 `--field-bg` / `--field-border`；分栏摘要和只读字段使用 `--surface-secondary`，不得在组件内写死 `#0d1117`、`#161b22` 等近黑色背景。

## 5. 尺寸与间距

### 5.1 控件高度

| 档位 | 高度 | 用途 |
|---|---:|---|
| `sm` | 20px | 表格行内操作、紧凑标签 |
| `regular` | 24px | 默认按钮、输入框、筛选控件 |
| `lg` | 28px | 工具栏、对话框主表单 |

同一行内的按钮、输入框、下拉框和分段控件必须同高。

触控设备上的独立操作目标不小于 44px；桌面鼠标环境保持紧凑尺寸。

### 5.2 间距

只用 4px 网格：

```text
4 / 8 / 12 / 16 / 20 / 24 / 32
```

对应令牌：`--space-1` 到 `--space-8`。

- 图标与文字：4px 或 6px。
- 同排控件：8px。
- 表单字段之间：12–16px。
- 卡片内部：16px 或 20px。
- 页面区块之间：24px。

禁止随手写 7px、13px、17px、18px 这类无法归组的间距。

列表留白规则：

- 列表容器左右内边距必须为 0。
- 水平内边距由每个列表行承担，桌面通常使用 `--space-4`，窄屏通常使用 `--space-3`。
- 分隔线、悬停背景和选中背景必须铺满列表宽度，不能只覆盖文字内容区。
- 只有滚动条避让或列表外层布局需要时才调整容器，不得用容器 padding 代替行内 padding。
- 窄侧栏中的状态提示必须保持单行，空间不足时使用省略号并提供完整标题，不允许把最后一两个字挤到下一行。

### 5.3 下拉选择

- 禁止使用原生 `<select>` 的功能弹层；操作系统菜单无法跟随 8小时工作台的浅色、深色和材质规范。
- 标准下拉统一使用 `components/ui/UiSelect.vue`，分类快捷切换使用它的 `chip` 变体，可搜索输入使用 `UiCombobox`。
- 触发器高度必须与同排输入框一致：`sm` 20px、`regular` 24px、`lg` 28px；触控环境最小点击高度 44px。
- 菜单统一使用不透明 raised surface（`--dropdown-bg`）、`--dropdown-border`、`--dropdown-radius`、`--dropdown-shadow`；默认位于触发器下方 4px，空间不足时向上展开，不得让背后正文透出。
- 菜单内边距 4px，选项高度 32px；悬停使用 `--hover-bg`，选中使用 `--selection-bg`，选中项右侧或左侧必须显示勾选图标。
- 分类 chip 保持 20px 高度、4px 圆角和分类语义色，但展开后的菜单仍使用上述统一下拉材质。
- 下拉必须支持点击外部关闭、`Esc` 关闭、方向键切换、`Home` / `End` 跳转、`Enter` / `Space` 选择，并在选择后把焦点还给触发器。
- 工作空间切换和其他非模态选择菜单必须复用同一组下拉视觉令牌，不得另造圆角、阴影或高饱和选中背景。
- 工作空间图标只提供图片上传，不再展示预置图标和颜色选择器；未上传时使用默认线性图标兜底。
- 工作空间切换菜单从触发器左侧向右展开，禁止反向伸入侧边栏或被父容器裁切。
- 上传图片支持 PNG、JPEG、WebP，统一居中裁切为 192×192 后按用户隔离保存，不接收 SVG 或名称缩写占位。

## 6. 圆角、阴影和描边

### 6.1 圆角

| 元素 | 令牌 | 值 |
|---|---|---:|
| 徽章 | `--radius-badge` | 4px |
| 按钮 / 输入框 | `--radius-control` | 6px |
| 面板 / 菜单 | `--radius-panel` | 10px |
| 窗口 / 弹窗 | `--radius-window` | 12px |
| 大卡片 | `--radius-card` | 16px |

### 6.2 阴影

- 控件：`var(--shadow-control)`
- 页面内面板：`var(--shadow-panel)`
- 菜单 / Popover：`var(--shadow-popover)`
- 窗口 / 对话框：`var(--window-shadow)`

阴影必须按层级选择，不能所有元素共用一档。

### 6.3 描边

- 优先使用 0.5px 发丝线、透明度分隔和底色差。
- 不给页面里的每张卡片都加 1px 实线边框。

### 6.4 弹窗滚动结构

- 标准弹窗分为固定头部、唯一滚动正文、固定 footer 三段；窗口按钮、标题和底部主操作不得随滚轮移动。
- 所有弹窗必须使用 `UiDialog` 或基于它封装的 `UiConfirmDialog`，禁止业务组件自行复制遮罩、交通灯和焦点循环。
- 简单长内容使用 `UiDialog` 的 `scroll-mode="body"`；需要固定内部工具栏或列表时使用默认 `contained`，只让明确的正文子区域滚动。
- 弹窗整体禁止设置 `overflow-y: auto`，不存在整窗滚动模式；交通灯、标题和 footer 在任何情况下都必须保持固定。
- 弹窗正文是唯一滚动容器，必须使用 `overscroll-behavior: contain`；不要在正文内部再创建第二个纵向滚动区。
- footer 通过 `#footer` 插槽渲染，保持不透明 raised surface、顶部发丝线和右对齐操作，不放进滚动正文。
- 头部、正文和 footer 的横向内边距必须一致；移动端统一使用 16px。
- 分隔线使用 `--line-soft`；只有真正需要阻断视觉流时才使用 `--line`。
- 输入框和按钮通过 `--control-border` / `--control-shadow` 表达边界。

## 7. 基础组件

### 7.1 按钮

统一使用 `components/ui/UiButton.vue`。

| `variant` | 用途 |
|---|---|
| `default` | 取消、次要操作、普通动作 |
| `primary` | 当前区域唯一主操作 |
| `danger` | 明确且不可逆的破坏性提交 |
| `ghost` | 工具栏、低优先级动作 |
| `danger-ghost` | 删除入口、不会抢占主操作视线的危险动作 |

规则：

- 一个操作区只允许一个 `primary`。
- 按钮文案使用动词，如“保存”“添加网址”“重新连接”。
- 不使用只有图标且没有可读标签的关键业务按钮。
- 业务页面不得覆盖按钮高度、圆角、字号和内边距。

### 7.2 输入框与字段

统一使用：

- `components/ui/UiInput.vue`
- `components/ui/UiFormField.vue`

页面表单使用上下排布：

```text
字段名
┌──────────────────────┐
│ 输入值               │
└──────────────────────┘
字段说明
```

macOS 对话框内使用左右排布：

```text
    名称  ┌──────────────────────┐
          │ 输入值               │
          └──────────────────────┘
          字段说明跟随控件
```

规则：

- 标签 13px 主文本色。
- 说明 11px 次要文本色，放在控件下方。
- 校验信息紧贴对应字段，不只放在表单底部。
- 聚焦时边框变系统蓝并显示轻微外发光。
- 错误输入使用系统红边框，同时给出文字原因。

### 7.3 分段控件

统一使用 `components/ui/UiSegmentedControl.vue`。

- 用于 2–4 个互斥选项，不用于页面导航。
- 灰色轨道、白色滑块、当前项 500 字重。
- 不使用彩色胶囊表示选中。

### 7.4 窗口控制

真实窗口使用 `components/ui/TrafficLights.vue`：

- 红黄绿 12px，间距 8px。
- 三颗按钮必须可以关闭、最小化和最大化。
- 图标只在悬停或键盘聚焦时出现。

模态窗口：

- 只有红点可关闭。
- 黄绿保留系统本色，但降低透明度表示不可用。
- 不允许摆放点击后没有任何行为的假按钮。

## 8. 对话框

8小时工作台对话框遵循 macOS `NSAlert` / 原生表单弹窗的空间关系：

1. 面板宽度：短表单 440px，长表单 640px。
2. 左上角放置窗口红黄绿。
3. 标题 13px，说明 11px，文字左对齐。
4. 正文区域唯一允许滚动；标题和底部按钮固定。
5. 按钮位于右下角，顺序为“取消在左、主操作在右”。
6. 删除入口位于左下角，使用 `danger-ghost`。
7. 遮罩只压暗，不用高饱和颜色或大面积毛玻璃。
8. 默认点击遮罩不关闭，避免误丢用户输入。
9. `Esc` 关闭；打开时焦点进入首个字段；关闭后焦点回到触发元素。
10. `Tab` 和 `Shift+Tab` 必须在弹窗内部循环。
11. 所有业务弹窗必须使用 `UiDialog` 的固定高度档位，内容多少、加载状态、校验信息和标签页切换都不能改变弹窗外部高度。
12. 高度档位统一为 `compact` 360px、`standard` 560px、`tall` 680px；实际高度按当前视口安全收缩，业务组件不得自行写死像素高度。
13. `standard` 是默认档位；短表单使用 `compact`，包含多标签页、长列表或复杂操作区的弹窗使用 `tall`。
14. `height="auto"` 只允许用于确认框和内容明确的短时提示，不得用于会切换内容视图的业务弹窗。
15. 固定高度弹窗的空间变化只能发生在正文滚动区；头部、筛选工具栏和 footer 不得因内容变化移动。

禁止：

- 页面后台常见的灰色标题条 + 大面积蓝色图标块。
- 22px 以上弹窗标题。
- 顶部右侧再放一个普通网页关闭叉号，与交通灯重复。
- 主按钮带对勾图标；macOS 的系统蓝按钮本身已经足够明确。
- 根据当前标签页、加载结果或列表数量动态设置弹窗高度。

## 9. 页面骨架

桌面端采用：

```text
┌─────────────────────────────────────────────┐
│ Titlebar 46px（材质 + 交通灯 + 页面标题）    │
├──────────────┬──────────────────────────────┤
│ Sidebar      │ Toolbar + Content            │
│ 216px（材质） │                              │
└──────────────┴──────────────────────────────┘
```

- 标题栏必须真实支持窗口操作。
- 侧边栏只放业务入口，个人资料与设置统一从顶部头像菜单进入。
- 品牌区固定在侧边栏顶部，主业务导航独立滚动。
- 应用版权 footer 横跨整个窗口底部，位于侧边栏和内容区之外；中间显示 `© 2026 panyong`，右侧提供“打卡/下班”和带无障碍名称的咖啡杯“休息一下”按钮。
- 导航超出可用高度时必须支持鼠标滚轮和触控板滚动，并显示稳定的 8px 滚动条；不得依靠压缩行高或强制收起菜单来规避溢出。
- 顶部账户入口只显示头像；姓名、邮箱和账户操作在弹出菜单中展示，避免占用工具栏宽度。
- “数据与集成”中的 Codex 固定展示官方名称和图标，不得复用 Codex 助手的自定义昵称或头像。
- 工作台作为独立入口，不归入任何分组；“日常”包含 Codex、速记、日历和邮件，“研发”包含工作目录、Git 仓库、数据库、服务器、部署和 Bug 清单，“资源”包含网址、App 和密码库。
- Git 操作页将远端同步、分支操作和提交变更依次纵向排列；合并入口只显示按钮，来源分支必须在弹框中选取。
- 一级菜单高度 34px，右侧用 14px 展开箭头；二级菜单高度 30px，左侧缩进 12px 并以发丝线连接层级。
- 当前菜单页面必须同步到 URL 的 `view` 查询参数，刷新后恢复原页面并保持对应菜单激活。
- 将列表记录移动到其他工作空间后必须保持当前工作空间，不得自动切换顶部工作空间。
- 内容区使用白色或浅灰画布，卡片使用 `--canvas-raised` + `shadow-panel`。
- 页面顶部只保留一个主标题；不用英文眉题、全大写英文和超大留白重复表达。
- 业务页面需要“已经看懂、马上能操作”的信息密度。

响应式以 1024px 作为桌面 / 手机分界：

- 小于 1024px 时侧边栏变抽屉。
- 小于 760px 时工具栏允许换行。
- 小于 520px 时对话框字段从左右排布切为上下排布。
- 页面不得出现横向滚动。

## 10. 工作台专属规范

### 10.1 时间区

- 使用深色玻璃 Widget，作为工作台唯一允许大面积深色的组件。
- 时间数字是视觉焦点，但不得挤占网址和软件入口的首屏空间。
- 工作节奏、日期和时区使用 11px 元信息，不使用 7–9px 微缩文字。

### 10.2 常用网址与本地软件

- 使用 Launchpad 式图标网格。
- 桌面最多 8 列，中等宽度 6–7 列，手机 4 列。
- 图标尺寸 42px，名称 11px，辅助域名 / 路径 11px。
- 添加入口固定在分区标题右侧，使用中性“+”图标，不占用网址网格单元。
- 编辑入口悬停出现；触屏常显。
- 悬停反馈只作用于图标本身（轻微抬升与控件阴影），不要给整个“图标 + 标题 + 域名”区域铺灰色选中底。
- 网站图标优先使用真实 favicon；失败时显示地球线性图标。
- 本地软件优先使用系统图标；失败时显示应用窗口线性图标。
- 图片成功加载后必须移除回退占位，不能让透明 PNG / SVG 透出背后的地球或窗口图标。
- **任何快捷图标内都不自动生成字母、汉字或名称缩写。**
- 自定义图标必须保持方形裁切和统一圆角。
- 网址管理页通过左侧分类栏筛选全部网址；分类可以独立新增，与是否已有网址无关；新增和编辑网址时必须可以指定分类。
- 分类支持拖拽排序，排序结果必须持久化；同时提供 `Option + ↑/↓` 的键盘排序方式。
- 工作台只展示全部网址中点击量最高的 10 条，同点击量时按创建时间倒序排列。
- 从工作台或网址管理页成功打开一次网址，点击量加一；加载或打开失败不计入点击量。
- App 管理行本身不启动应用；行尾独立的“播放图标 + 打开”按钮是唯一启动动作。
- App 列表通过一次批量宿主检测显示运行状态，并在窗口重新聚焦、页面恢复可见及固定间隔自动刷新。
- 已运行的 App 显示中性色“已打开”状态与绿色状态点，打开按钮用于切换到前台；未运行时禁用强制退出。

### 10.3 服务器管理

- 服务器行本身不触发连接；行尾独立的“终端图标 + 连接”按钮是唯一 SSH 连接动作，必须提供 `aria-label` 和悬停提示。
- “文件”动作进入内置 SFTP 文件管理，不能与 SSH 连接图标合并或使用整行点击代替。
- 服务器行只保留内置终端、文件管理和编辑入口，不再提供第三方客户端菜单。
- 列表不得显示密码、密码密文或任何可还原凭据的信息。
- 终端使用独立的深色窗口材质和等宽字体；连接状态、主机指纹和重连入口必须持续可见。
- SFTP 文件列表保持高信息密度，目录优先排序；上传、下载、新建目录和删除使用明确文字或带提示的图标按钮。
- 涉及密码、会话令牌、主机密钥或用户路径的报错不得输出到控制台、URL 或剪贴板。

### 10.4 Codex 会话

- 会话行保留整行选择行为，删除使用行尾独立的垃圾桶图标按钮。
- Codex 连接状态显示在会话面板标题区，不占用当前会话的目录和任务操作栏。
- 删除必须经过二次确认，并明确会移除本机会话及其任务记录。
- 运行中的会话禁止删除，并提示先停止任务。
- 删除最后一个会话后展示空状态，不自动创建新的“新会话”。
- 停止任务时按钮必须进入明确的“正在停止”状态；app-server 已退出时不得等待 initialize 超时，应立即结束本地残留任务状态。
- 会话正文必须按事件到达顺序渲染，文字、命令、文件和搜索操作穿插在同一条时间线中；不得先聚合全部回复再聚合全部操作。
- 任务运行中仍允许输入，后续消息进入本地队列；当前任务结束后按顺序自动启动队首任务，队列项必须可单独取消。
- Codex 运行中只有一个右下角主按钮：输入为空时显示停止，有可发送内容时切换为发送；不得并排显示停止和发送。
- Codex 正文使用 13px / 21px 行高，操作文字使用次级灰色，行内代码使用独立浅灰底；颜色和字号统一消费 `--codex-message-*` 与 `--codex-inline-*` 令牌。
- Codex 操作行使用 25px 行高、12px 行间距和固定 16px 图标列，并按搜索、图片、文件、命令等语义选择同一套线性图标。
- 连续命令操作必须聚合为可折叠命令组，默认收起；展开后仍展示每条命令，分组不得跨越穿插的正文或其他类型操作。
- Codex 命令折叠摘要与展开后的命令明细统一使用方形终端图标。
- 文件编辑详情及编辑摘要统一使用同尺寸铅笔图标，不使用文件加铅笔的组合图标。
- 关联 Bug 的任务成功创建后必须清空输入框中的 Bug 选择，同时把该 Bug 上下文保存在新任务中。

### 10.5 随笔

- 使用“记录流 + 编辑区”双栏结构，不采用卡片瀑布流。
- 记录标题可留空并取正文首行，正文自动保存，不增加额外保存步骤。
- 自动标题已经使用正文首行时，记录流摘要必须跳过该行，不能重复展示同一句内容。
- 按“置顶、今天、昨天、日期”组织时间线；重要、归档和标签使用中性元数据样式。
- 已解决记录在记录流中必须使用删除线，并提供独立的“已解决”筛选；状态可以恢复。
- 新建、置顶、重要、归档和删除必须使用独立图标按钮，并提供无障碍名称与悬停提示。
- 删除必须二次确认；空状态提供新建入口和 `Command + Shift + N` 快捷记录提示。
- 桌面和移动端都必须保持可编辑、可搜索且无横向溢出。

### 10.6 密码库

- 未解锁时只展示验证页，不加载、不展示任何密码条目。
- 支持登录密码和平台认证（Touch ID）；平台认证能力不可用时保留密码方式作为兜底。
- 验证成功后明确显示剩余解锁时间，过期立即清空内存中的密码明文并回到锁定页。
- 列表中禁止直接展示密码；查看和复制必须使用独立操作按钮，密码按需读取。
- 密码字段默认隐藏，编辑时留空表示不修改原密码。
- 密码库分类沿用工作目录的分类筛选条和管理弹窗；分类新增、重命名、删除迁移及行内快捷移动必须完整可用。
- 密码库行尾操作按钮之间使用 `--space-2`，不得以贴边图标挤压可点击区域。
- 密码库使用独立 HttpOnly 解锁 Cookie，解锁文案不能泄露密码或验证凭据。
- 密码库列表的分类使用固定网格列；网址以无底色的系统蓝链接展示，悬停或聚焦时增加下划线与高亮。

### 10.7 今日关怀

- 工作台提供喝水、起身活动和洗手间三个一键记录动作，并显示今日次数与目标。
- 底部提供每日一次的上班打卡、首次下班打卡和后续更新时间操作；未打卡时不得开始工作休息计时。
- 提醒设置按周一至周日保存班次；每天独立配置工作日开关、上班时间、下班时间和上下班打卡提醒，并支持统一提前提醒分钟数。
- 点击“休息一下”会记录休息区间并从净工作时长中扣除，继续工作后回到当前工作时段。
- “休息一下”与上下班打卡相互独立，未打卡或已下班时也可开始休息；只有已经在休息时才禁止重复开始。
- 连续工作默认 60 分钟提示喝水、90 分钟提示起身活动；完成对应动作后重新计时。
- “休息一下”进入全屏休息屏保，显示实时休息时长；只有点击“继续工作”才结束并写入休息区间。
- 休息屏保使用 `UiDialog` 的 `screensaver` 变体，必须保留焦点循环和 `Esc` 退出能力。
- 关怀记录支持查看今日完整时间线、工作时间曲线、打卡、休息时段及最近 30 天历史；历史记录按天汇总并可展开。
- 关怀数据按登录账号隔离，必须通过 `services/userScopedStorage.ts` 持久化，禁止写入全局 `localStorage`。

## 11. 图标

- 统一使用 `@lucide/vue`。
- 常规 16px、工具栏 18–20px、空态 28–32px。
- 同一行图标视觉尺寸和描边重量必须一致。
- 普通操作图标默认使用 `var(--icon)`，悬停使用 `var(--icon-hover)`；同一组操作不得因为功能不同而使用不同图标颜色。
- 列表行内图标操作按钮默认不显示背景色，仅在悬停或键盘聚焦时提供反馈。
- 所有删除/垃圾桶图标在默认、悬停和聚焦状态均使用 `var(--system-red)`；悬停背景使用 8% 系统红，不接受灰色删除图标。
- 系统语义色只用于成功、警告、错误、选中和平台类型等确有含义的图标，不用于装饰普通操作按钮。
- 图标与文字的间距优先使用 `--space-2`，同排独立按钮之间至少使用 `--space-2`。
- 纯装饰图标设置 `aria-hidden="true"`。
- 没有文字说明的图标按钮必须提供 `aria-label` 和悬停提示。
- 不用 emoji 代替界面图标。

## 12. 动效与反馈

| 场景 | 时长 |
|---|---:|
| 悬停、颜色 | 120ms |
| 菜单、分段滑块 | 160ms |
| 窗口、面板入场 | 200ms |

统一缓动：`var(--ease-apple)`。

- 弹窗只淡入 + 轻度缩放，不滑入。
- 按钮按下最多 `scale(0.98)`。
- 禁止 Material 涟漪、弹跳、持续呼吸和装饰性粒动效。
- 尊重 `prefers-reduced-motion`。
- 成功提示说明“发生了什么”，失败提示说明“为什么”和“下一步”。

## 13. 焦点、滚动条与可访问性

- 鼠标点击不显示焦点环，键盘操作必须显示。
- 全局兜底使用 `outline`；输入框使用边框 + 轻微外发光。
- 滚动条宽 8px，默认透明，悬停时淡入。
- 键盘可以到达所有交互控件。
- 账户、工作空间等非模态菜单必须支持点击外部关闭、`Esc` 关闭，并在选择菜单项后关闭；菜单内部点击不能触发外部关闭。
- 颜色不能是状态的唯一表达，必须配合文字或图标。
- 弹窗具备 `role="dialog"`、`aria-modal`、标题和说明关联。
- 长文本允许截断，但必须能通过标题提示、详情或弹层读取完整内容。
- 用户资料、网址、分类、快捷方式、工作目录和主题必须通过 `services/userScopedStorage.ts` 按账号隔离；`pnpm check:isolation` 会阻止新增全局 localStorage 读写。

## 14. 明确禁止

1. 小于 11px 的业务文字。
2. 在业务组件中直接写新的十六进制颜色、字体栈或阴影。
3. 给页面里的每张卡片加 1px 边框，形成线框图。
4. 使用 7–10px、全大写英文、夸张字距制造“高级感”。
5. 使用彩色胶囊、渐变按钮、渐变卡片或背景光斑。
6. 使用 emoji 作为主要功能图标。
7. 使用假的红黄绿按钮。
8. 在 favicon 缺失时用名称首字母代替图标。
9. 弹窗点击遮罩关闭并丢失表单内容。
10. 只实现浅色模式。
11. 只在宽屏验证。
12. 用 `!important` 修复组件样式冲突；应回到变体或令牌修复。

## 15. 开发流程

应用内入口：**设置 → 设计系统 → 样式规范**。修改令牌或基础组件后，同步检查该面板是否仍与规范一致。

新增或修改界面前：

1. 先读本规范与 `tokens.css`。
2. 查找现有 `components/ui/` 组件，优先复用。
3. 业务组件只写布局和业务状态，不重写控件视觉。
4. 同一视觉重复两次以上时抽基础组件。

提交前必须执行：

```bash
cd workcove-web
pnpm check:ui
pnpm check:isolation
pnpm typecheck
pnpm build
```

涉及页面的改动还必须：

1. 在浅色和深色下检查。
2. 在 `1280×800` 和 `390×844` 下检查。
3. 确认没有横向溢出、文字遮挡和不可点击区域。
4. 检查空态、加载态、错误态、长文本和键盘焦点。
5. 如果改了弹窗，检查打开、`Esc`、`Tab` 循环和焦点返回。

## 17. 变更原则

- 视觉规范变更必须修改本文件，并同步 `tokens.css`。
- 只修改某个页面、但会影响其他页面的视觉值，不得写在页面局部样式中。
- 已有页面在功能改动时顺带迁移到规范；不为追求一次性“全站重构”引入与当前任务无关的大范围风险。
- 发现规范阻碍真实业务场景时，先提出新的语义令牌或组件变体，不在调用点临时绕过。
